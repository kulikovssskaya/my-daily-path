# Базы данных — ER-модель, OLTP/OLAP, ETL

> `#Databases` `#SQL` `#Analytics` `#OLAP`
>
> Как организованы данные для транзакций и для аналитики.

## Ключевые концепции

- **ER-модель / ER-диаграмма** — сущности и связи между ними.
- **OLTP** — обработка транзакций (нормализованные данные).
- **OLAP** — аналитическая обработка (многомерные данные, OLAP-куб).
- **Схемы «звезда» и «снежинка»** — организация аналитического хранилища.
- **ETL** — extract, transform, load.

## Подробное объяснение

### ER-модель

- **ER-модель (Entity-Relationship)** — описание предметной области в терминах
  **сущностей** и **связей** между ними.
- **ER-диаграмма** — визуализация ER-модели (таблицы и связи).

### OLTP vs OLAP

| | **OLTP** | **OLAP** |
|---|---|---|
| Назначение | Обработка транзакций реального мира | Аналитические отчёты |
| Данные | Транзакционные | Многомерные (агрегаты) |
| Структура | Нормализованная | Денормализованная (звезда) |
| Пример | Оформление заказа | Отчёт о продажах по регионам |

![OLTP vs OLAP: транзакционная обработка vs аналитические запросы](/kb-img/oltp-olap.svg)

- **OLTP (OnLine Transaction Processing)** — эффективная обработка большого числа
  событий; требует **нормализации**. **Транзакция** — минимальная логическая
  операция: выполняется либо полностью, либо не выполняется вообще.
- **OLAP (OnLine Analytical Processing)** — упрощает подготовку аналитических
  отчётов. **OLAP-куб** — геометрическое представление многомерных данных.

### Схемы хранилища

![Схема «звезда»: fact-таблица в центре и dimension-таблицы вокруг](/kb-img/star-schema.svg)

- **Звезда (star schema)** — в центре одна таблица фактов, вокруг — таблицы
  измерений. **Денормализована** (быстрее для аналитики).
- **Снежинка (snowflake)** — измерения дополнительно нормализованы (меньше
  дублирования, но больше соединений).

### ETL

**ETL (Extract, Transform, Load)** — извлечь данные из источников, преобразовать
к общему формату и загрузить в единую точку аналитической обработки (обычно —
корпоративное хранилище с OLAP-структурой).

## Практическая реализация (SQL)

```sql
-- View: именованная виртуальная таблица (результат SELECT)
CREATE VIEW salesmen_stats AS
SELECT salesman_id, COUNT(*) AS deals, SUM(amount) AS revenue
FROM sales
GROUP BY salesman_id;
```

## Лучшие практики и подводные камни

- ✅ OLTP — нормализуйте (3NF) для целостности транзакций.
- ✅ OLAP — денормализуйте (звезда) для скорости аналитических запросов.
- ⚠️ Не запускайте тяжёлую аналитику на боевой OLTP-базе — используйте отдельное хранилище.
