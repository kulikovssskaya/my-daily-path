## Ключевые концепции

- **Парадигмы обучения:** supervised, unsupervised, semi-supervised, reinforcement.
- **Типы задач:** классификация, регрессия, кластеризация.
- **Признаки:** числовые и категориальные; стандартизация; проклятие размерности; PCA.
- **Параметры модели:** веса (weights) и смещение (bias).
- **Метрики:** MAE, MSE, R², precision, recall, F1, ROC-AUC, PR-AUC.
- **Модели:** линейные, деревья, ансамбли (bagging / boosting / stacking), kNN.
- **Борьба с переобучением:** регуляризация, упрощение модели, аугментация данных.
- **Кросс-валидация:** k-fold, stratified, leave-one-out, time-series split.

## Подробное объяснение

### 2.1 Парадигмы и типы задач ML

#### Парадигмы обучения

| Парадигма | Есть разметка? | Суть | Примеры задач |
|-----------|----------------|------|---------------|
| **Supervised** (с учителем) | Да | Модель учится по парам «признаки → ответ» | Классификация, регрессия |
| **Unsupervised** (без учителя) | Нет | Модель ищет структуру в данных | Кластеризация, снижение размерности |
| **Semi-supervised** (полу-контролируемое) | Частично | Мало размеченных + много неразмеченных данных | Разметка текста, CV |
| **Reinforcement** (с подкреплением) | Награда | Агент учится действиям в среде | Игры, робототехника |

> Классическое ML в аналитике — это прежде всего **обучение с учителем**: классификация и регрессия.

#### Типы задач

| Задача | Тип таргета | Что делает | Пример |
|--------|-------------|-----------|--------|
| **Классификация** | Категория (конечное множество) | Предсказывает класс | Спам / не спам |
| **Регрессия** | Непрерывное число | Прогнозирует величину | Цена квартиры |
| **Кластеризация** | Нет (unsupervised) | Группирует по сходству | Сегментация клиентов |

Классификация бывает **бинарной** (2 класса) и **многоклассовой** (> 2 классов).

![Три типа задач ML: классификация, регрессия, кластеризация; supervised vs unsupervised](/kb-img/ml-task-types.svg)

#### Алгоритмы по типу задачи

| Задача | Типичные алгоритмы |
|--------|-------------------|
| Классификация | Логистическая регрессия, деревья, Random Forest, бустинг, kNN, нейросети |
| Регрессия | Линейная регрессия, деревья, бустинг, kNN |
| Кластеризация | K-Means, иерархическая, DBSCAN |

### 2.2 Признаки, стандартизация и проклятие размерности

#### Типы признаков

| Тип | Описание | Примеры |
|-----|----------|---------|
| **Числовые** | Имеют математический смысл, можно усреднять | Возраст, доход, пробег |
| **Категориальные** | Метки без порядка или с порядком | Цвет, регион, уровень образования |

> ⚠️ Категориальные признаки, закодированные числами (код региона `77`), нельзя
> трактовать как непрерывные — их нужно кодировать (One-Hot, target encoding и т.д.).

#### Параметры модели

Линейные и нейросетевые модели оперируют двумя видами обучаемых параметров:

- **Веса (weights, $w$)** — коэффициенты при признаках; показывают вклад каждого признака.
- **Смещение (bias, $b$)** — свободный член; сдвигает предсказание независимо от признаков.

#### Стандартизация

**Стандартизация** (Z-масштабирование) приводит признаки к сопоставимому масштабу:
$z = (x - \mu) / \sigma$. Это важно для линейных моделей, kNN, SVM и нейросетей.

> 💡 **Деревьям и бустингу на деревьях нормализация не обязательна** — сплиты
> зависят от порядка значений, а не от абсолютного масштаба.

#### Сколько признаков — достаточно?

| Ситуация | Последствия |
|----------|-------------|
| Умеренное число информативных признаков | Обычно хорошо |
| Признаков **больше**, чем объектов ($p > n$) | Риск переобучения, нестабильные веса |
| Очень много признаков | **Проклятие размерности**: в векторном пространстве объекты «сближаются», расстояния теряют смысл; модель обучается дольше |

**Как убрать лишние признаки:**

| Метод | Описание |
|-------|----------|
| Вручную | Экспертный отбор по доменным знаниям |
| Удаление мультиколлинеарных | Признаки с линейной зависимостью (высокая корреляция / VIF) |
| **L1-регуляризация (Lasso)** | Зануляет малозначимые веса → автоматический отбор |
| Важность в деревьях | Сумма прироста информативности по признаку |

**Снижение размерности** (сохраняем структуру, уменьшаем число осей):

| Метод | Назначение |
|-------|-----------|
| **PCA** | Линейное сжатие, максимум дисперсии |
| **t-SNE** | Визуализация кластеров (нелинейно, медленно) |
| **UMAP** | Визуализация и иногда препроцессинг (быстрее t-SNE) |

![PCA: проекция данных на главные компоненты с максимальной дисперсией](/kb-img/pca.svg)

```python
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler

X_scaled = StandardScaler().fit_transform(X)
X_pca = PCA(n_components=10).fit_transform(X_scaled)
```

### 2.3 Метрики качества

#### Метрики регрессии

| Метрика | Формула / суть | Особенности |
|---------|----------------|-------------|
| **MAE** | Средняя абсолютная ошибка | Устойчива к выбросам, интерпретируема |
| **MSE** | Средний квадрат ошибки | Сильнее штрафует большие ошибки |
| **RMSE** | $\sqrt{\mathrm{MSE}}$ | В тех же единицах, что и таргет |
| **$R^2$** | Доля объяснённой дисперсии | 1 — идеально, 0 — как среднее, < 0 — хуже среднего |
| **MAPE** | Средняя относительная ошибка в % | Удобна для бизнеса, не работает при нулевых значениях |

**Асимметричные функции потерь** — по-разному штрафуют переоценку и недооценку.
Пример: в кредитном скоринге лучше **недооценить** платёжеспособность (выдать меньше),
чем переоценить; в прогнозе спроса переоценка ведёт к излишкам на складе.

```python
from sklearn.metrics import mean_absolute_error, mean_squared_error, r2_score

mae = mean_absolute_error(y_true, y_pred)
rmse = mean_squared_error(y_true, y_pred, squared=False)
r2 = r2_score(y_true, y_pred)
```

#### Метрики бинарной классификации

**Accuracy** — доля верных предсказаний. Проста, но **обманчива при дисбалансе классов**.

| Метрика | Что измеряет |
|---------|-------------|
| **Precision** | Доля истинно положительных среди предсказанных положительных |
| **Recall** | Доля найденных положительных среди всех реальных положительных |
| **F1** | Среднее гармоническое precision и recall |

![Матрица ошибок 2x2: TP, FP, FN, TN и формулы precision, recall, F1](/kb-img/confusion-matrix.svg)

| Кривая / площадь | Оси | Заметки |
|------------------|-----|---------|
| **ROC-AUC** | TPR vs FPR | Неустойчива при сильном дисбалансе |
| **PR-AUC** | Precision vs Recall | Предпочтительнее при редком целевом классе |

```python
from sklearn.metrics import (accuracy_score, precision_score, recall_score,
                             f1_score, roc_auc_score, average_precision_score,
                             classification_report)

print(classification_report(y_test, y_pred))
roc_auc_score(y_test, y_proba)
average_precision_score(y_test, y_proba)  # PR-AUC
```

#### Метрики многоклассовой классификации

| Усреднение | Как считается | Когда использовать |
|------------|---------------|-------------------|
| **Micro** | Глобально по всем TP/FP/FN матрицы | Когда важна общая точность |
| **Macro** | Метрика по каждому классу, затем среднее | Когда все классы равноценны |
| **Weighted** | Macro с весами по числу объектов класса | Компромисс при дисбалансе |

> ⚠️ Micro-F1 на несбалансированных данных может «маскировать» слабый recall
> редкого класса — смотрите отчёт по каждому классу отдельно.

### 2.4 Линейные модели

**Линейная модель** — предсказание как линейная комбинация признаков:
$\hat{y} = \mathbf{w}^\top \mathbf{x} + b$.

Две основные модели:

| Модель | Задача | Функция потерь | Выход |
|--------|--------|----------------|-------|
| **Линейная регрессия** | Регрессия | MSE | Непрерывное число |
| **Логистическая регрессия** | Бинарная классификация | Log loss (кросс-энтропия) | Вероятность через сигмоиду |

**Log loss** (логистическая потеря) штрафует уверенные ошибочные предсказания:

$$
\mathcal{L} = -\frac{1}{n}\sum_{i=1}^{n}\left[y_i \log p_i + (1 - y_i)\log(1 - p_i)\right]
$$

Для бинарной классификации таргет моделируется как **распределение Бернулли**
(исход «успех / неуспех» с вероятностью $p$).

#### Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| Быстрое обучение | Плохо улавливают нелинейные зависимости |
| Интерпретируемость весов | Чувствительны к выбросам |
| Не требуют большого объёма данных | Качество падает при мультиколлинеарности без регуляризации |

**Интерпретируемость:** положительный вес → признак увеличивает целевую переменную;
чем больше $|w|$, тем сильнее вклад. Сравнивать веса можно только **после нормализации**
признаков — иначе масштаб искажает важность.

**Регуляризация** (L1/L2) помогает бороться с переобучением и мультиколлинеарностью.
L2 (Ridge) уменьшает веса; L1 (Lasso) обнуляет часть из них.

**Евклидова норма (L2)** весов — $\|\mathbf{w}\|_2 = \sqrt{\sum w_j^2}$; используется
в Ridge-штрафе.

#### Как обучаются линейные модели

1. **Аналитическое решение** — веса находятся по формуле (нормальное уравнение для MSE).
2. **Градиентные методы** — итеративно двигаемся в сторону **антиградиента** функции потерь.
   Для ускорения используют **мини-батчи** (градиент по подвыборке, а не по всему датасету).

```python
from sklearn.linear_model import LinearRegression, LogisticRegression

lr_reg = LinearRegression()
lr_reg.fit(X_train, y_train)

lr_clf = LogisticRegression(penalty="l2", C=1.0, max_iter=1000)
lr_clf.fit(X_train, y_train)
lr_clf.predict_proba(X_test)
```

### 2.5 Деревья решений

**Решающее дерево** — рекурсивное разбиение пространства признаков на области с однородным ответом.

#### Алгоритм построения

1. В корень помещаем весь датасет.
2. Выбираем **лучший признак** и **порог сплита**, максимизирующий критерий качества.
3. Разбиваем данные на две части.
4. Повторяем рекурсивно для каждой ветви.
5. **Останавливаемся** по критерию остановки → вершина становится **листом** с предсказанием (класс / среднее / медиана).

![Дерево решений: узлы с условиями сплита и листья с предсказаниями](/kb-img/decision-tree.svg)

#### Критерии сплиттинга (классификация)

| Критерий | Суть | Скорость |
|----------|------|----------|
| **Джини (Gini)** | Вероятность неправильной классификации случайно выбранного объекта | Быстрее |
| **Энтропия** | $-\sum_i p_i \log p_i$, где $p_i$ — доля класса $i$ в узле | Чуть медленнее |

Для **регрессии** оптимальный сплит ищут по минимизации **MSE** в дочерних узлах.

#### Критерии остановки

- Ограничение **максимальной глубины**.
- Минимальное / максимальное число объектов в узле (`min_samples_leaf`, `min_samples_split`).
- Минимальный **прирост информативности** (если сплит почти ничего не даёт — останавливаемся).

#### Плюсы и минусы

| Плюсы | Минусы |
|-------|--------|
| Улавливают нелинейные зависимости | Легко переобучаются без ограничений |
| Интерпретируемость правил | Плохо экстраполируют тренды (берут среднее/медиану в листе) |
| Работают с пропусками, числами и категориями | Чувствительны к гиперпараметрам |
| Не требуют нормализации | Без pruning — каждый объект может попасть в свой лист |

**Регуляризация дерева:** гиперпараметры (`max_depth`, `min_samples_leaf`) и
**pruning** (обрезка веток после обучения — post-pruning).

**Важность признака** — сумма приростов информативности по всем сплитам, где
использовался данный признак.

```python
from sklearn.tree import DecisionTreeClassifier

tree = DecisionTreeClassifier(max_depth=5, min_samples_leaf=10, random_state=42)
tree.fit(X_train, y_train)
list(zip(X_train.columns, tree.feature_importances_))
```

### 2.6 Ансамбли: bagging, boosting, stacking

**Ансамбль** — комбинация нескольких моделей для повышения качества и устойчивости.

![Bagging (Random Forest) vs Boosting: параллельное усреднение vs последовательное исправление ошибок](/kb-img/bagging-boosting.svg)

| Метод | Идея | Пример |
|-------|------|--------|
| **Bagging** | Много слабых моделей на разных подвыборках; ответы **усредняем / голосуем** | Random Forest |
| **Boosting** | Модели строятся **последовательно**, каждая исправляет ошибки предыдущих | Gradient Boosting, AdaBoost |
| **Stacking** | Базовые модели предсказывают; **метамодель** учится на их предсказаниях | Стек из RF + LR + мета-LR |

**Random Forest** — bagging над решающими деревьями: каждое дерево обучается на
bootstrap-подвыборке и случайном подмножестве признаков.

#### Bias–variance decomposition

Ошибка модели раскладывается на три части:

$$
\text{Error} = \text{Bias}^2 + \text{Variance} + \text{Noise}
$$

- **Bias (смещение)** — систематическая ошибка (недообучение).
- **Variance (разброс)** — чувствительность к конкретной выборке (переобучение).
- **Noise (шум)** — неустранимая случайность в данных.

| Метод | Что уменьшает |
|-------|---------------|
| **Bagging** | Variance (разброс) — деревья глубокие, но усреднение стабилизирует |
| **Boosting** | Bias (смещение) — модели уже «низковариативны», добавляем точность |

> 💡 В bagging деревья **глубже** (разные, некоррелированные); в boosting первые
> деревья вносят наибольший вклад — удаление одного дерева из бустинга бьёт
> сильнее, чем из случайного леса. Bagging **сложнее переобучить**.

```python
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier

rf = RandomForestClassifier(n_estimators=300, max_depth=None, random_state=42)
gb = GradientBoostingClassifier(n_estimators=200, learning_rate=0.05, random_state=42)
```

### 2.7 Градиентный бустинг (XGBoost, LightGBM, CatBoost)

**Градиентный бустинг** — на каждом шаге:

1. Фиксируем функцию потерь.
2. Считаем **антиградиент** (псевдо-остатки) по текущим предсказаниям.
3. Обучаем новое дерево предсказывать этот антиградиент.
4. Добавляем дерево к ансамблю с шагом **learning rate**.

| Библиотека | Особенность построения деревьев |
|------------|--------------------------------|
| **LightGBM** | Leaf-wise: на каждом шаге делит лист с наилучшим gain; быстрый на больших данных |
| **XGBoost** | Level-wise: стремится к симметричным деревьям; сильная регуляризация |
| **CatBoost** | Ordered boosting, нативная работа с категориями; сильнее ограничивает форму деревьев |

```python
from lightgbm import LGBMClassifier
from catboost import CatBoostClassifier
import xgboost as xgb

lgbm = LGBMClassifier(n_estimators=500, learning_rate=0.05)
cat = CatBoostClassifier(iterations=500, cat_features=["region"], verbose=0)
xgb_model = xgb.XGBClassifier(n_estimators=500, learning_rate=0.05)
```

### 2.8 Метрические модели (kNN)

**Метрические модели** предсказывают по **сходству** нового объекта с обучающей выборкой.

**k-Nearest Neighbors (kNN):**

1. При обучении **запоминаем** всю выборку ($O(1)$).
2. При предсказании размещаем объект в пространстве признаков.
3. Находим $k$ ближайших соседей.
4. Ответ — **среднее** (регрессия) или **мода** (классификация).

| Метрика расстояния | Формула / суть |
|--------------------|----------------|
| **Евклидово** | $\sqrt{\sum (x_i - y_i)^2}$ — классика |
| **Манхэттенское** | $\sum |x_i - y_i|$ — устойчивее к выбросам по осям |
| **Косинусное** | Угол между векторами — для текстов / разреженных данных |

| Плюсы | Минусы |
|-------|--------|
| Простая реализация, интерпретируемость | Медленное предсказание ($O(n)$ на объект) |
| Не требует явного обучения | Чувствительность к масштабу признаков |
| | Проклятие размерности, нужно хранить всю выборку |

> 💡 Признаки для kNN должны быть в **согласованном масштабе** (StandardScaler).
> Ускорение: снижение размерности (PCA), алгоритмы приближённого поиска (Ball Tree, KD-Tree).

**Применение:** рекомендательные системы, поиск аномалий / мошеннических транзакций
по «отдалённым» объектам в пространстве признаков.

```python
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline

knn = Pipeline([
    ("scaler", StandardScaler()),
    ("clf", KNeighborsClassifier(n_neighbors=5, metric="minkowski", p=2)),
])
knn.fit(X_train, y_train)
```

### 2.9 Кластеризация

**Кластеризация** — обучение **без учителя**: модель сама находит группы похожих объектов.

| Тип | Описание |
|-----|----------|
| **Hard clustering** | Каждый объект принадлежит ровно одному кластеру |
| **Soft clustering** | Объект имеет вероятности принадлежности к нескольким кластерам (GMM) |

#### K-Means

1. Выбираем $k$ начальных центров (случайно или **k-means++** — равноудалённые точки).
2. Присваиваем каждый объект ближайшему центру.
3. Пересчитываем центры как среднее точек кластера.
4. Повторяем шаги 2–3 до сходимости.

**Ускорение:** k-means++, MiniBatch K-Means, понижение размерности, параллелизация.

```python
from sklearn.cluster import KMeans

km = KMeans(n_clusters=5, init="k-means++", n_init="auto", random_state=42)
labels = km.fit_predict(X)
```

#### Иерархическая агломеративная кластеризация

Начинаем с $n$ кластеров (каждая точка — отдельный кластер) и **попарно объединяем**
наиболее похожие, пока не останется один. Результат — **дендрограмма**.

**Связь между кластерами (linkage):**

| Метод | Расстояние между кластерами |
|-------|----------------------------|
| Single | Между двумя ближайшими точками |
| Complete | Между двумя дальними точками |
| Average / Ward | По центроидам или минимизации внутрикластерной дисперсии |

**Критерии остановки:** заданное число кластеров, «разрыв» на дендрограмме, порог по расстоянию.

#### DBSCAN

Группирует плотные области; изолированные точки помечает как **шум**.

| Параметр | Смысл |
|----------|-------|
| `eps` | Радиус окрестности |
| `min_samples` | Минимум точек для формирования кластера |

| Тип точки | Описание |
|-----------|----------|
| **Core** | В окрестности ≥ `min_samples` точек |
| **Border** | В окрестности core, но сама не core |
| **Noise** | Не core и не border |

| Плюсы | Минусы |
|-------|--------|
| Сам определяет число кластеров | Медленнее на больших $n$ |
| Устойчив к выбросам | Плохо в высоких размерностях |

#### Метрики оценки кластеризации

| Тип | Метрики |
|-----|---------|
| **С разметкой** (редко) | Гомогенность, полнота, V-мера (F-мера) |
| **Без разметки** | Внутрикластерное расстояние (↓ лучше), межкластерное (↑ лучше), **коэффициент силуэта** |

```python
from sklearn.metrics import silhouette_score, homogeneity_score, completeness_score

silhouette_score(X, labels)          # [-1, 1], чем выше — тем лучше
homogeneity_score(y_true, labels)    # нужна эталонная разметка
```

### 2.10 Многоклассовая классификация и балансировка классов

#### Схемы многоклассовой классификации

| Схема | Как работает | Моделей |
|-------|-------------|---------|
| **One-vs-Rest (OvR)** | Для каждого класса — бинарная модель «класс vs все остальные» | $K$ |
| **One-vs-One (OvO)** | Модель на каждую пару классов; итог — класс с наибольшим числом «побед» | $K(K-1)/2$ |
| **Встроенная (native)** | Деревья, нейросети предсказывают все классы сразу | 1 |

> В sklearn `LogisticRegression(multi_class="multinomial")` — нативная softmax-модель;
> `multi_class="ovr"` — One-vs-Rest.

#### Балансировка классов

| Метод | Описание |
|-------|----------|
| **Oversampling** | Добавить копии / синтетические примеры миноритарного класса (SMOTE) |
| **Undersampling** | Удалить часть объектов мажоритарного класса |
| **`class_weight`** | Взвешивание потерь в модели (`balanced` в sklearn) |

```python
from sklearn.linear_model import LogisticRegression
from imblearn.over_sampling import SMOTE  # pip install imblearn

lr = LogisticRegression(class_weight="balanced", max_iter=1000)
X_res, y_res = SMOTE(random_state=42).fit_resample(X_train, y_train)
```

### 2.11 Переобучение

**Переобучение (overfitting)** — модель запоминает тренировочные данные и плохо
обобщает на новые.

![Компромисс bias-variance: оптимум между недообучением и переобучением](/kb-img/bias-variance.svg)

#### Как бороться с переобучением

| Способ | Описание |
|--------|----------|
| **Регуляризация** | L1/L2, dropout, `max_depth` в деревьях |
| **Упрощение модели** | Меньше признаков, меньше параметров |
| **Больше данных** | Сбор новых примеров |
| **Аугментация** | Искусственное расширение выборки (повороты изображений, шум, SMOTE для таблиц) |

**Train / Validation / Test split:**

- **Train** — обучение модели.
- **Valid** — подбор гиперпараметров, ранняя остановка.
- **Test** — финальная оценка **один раз** в конце проекта.

> ⚠️ Test-выборку используйте **один раз** в самом конце; подбор гиперпараметров — на valid / через CV.

### 2.12 Кросс-валидация

**Кросс-валидация (CV)** разбивает данные на несколько фолдов и даёт **более честную
и стабильную** оценку, чем один train/test split. Особенно полезна при **малом объёме
данных** и **нестабильных выборках**.

![K-fold cross-validation: каждый фолд по очереди служит валидацией](/kb-img/cross-validation.svg)

| Вид CV | Когда использовать |
|--------|-------------------|
| **K-Fold** | Стандартный случай, $k = 5$ или $10$ |
| **Stratified K-Fold** | Несбалансированные классы — сохраняет доли классов в каждом фолде |
| **Leave-One-Out (LOO)** | Очень мало данных: $n$ фолдов по 1 объекту в тесте |
| **TimeSeriesSplit** | Временные ряды — тест всегда «в будущем» относительно train |

```python
from sklearn.model_selection import (train_test_split, cross_val_score,
                                     StratifiedKFold, TimeSeriesSplit)

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42, stratify=y
)

cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(pipe, X, y, cv=cv, scoring="f1_macro")
print(f"CV: {scores.mean():.3f} ± {scores.std():.3f}")

tscv = TimeSeriesSplit(n_splits=5)
```

> Смотрите на **среднее** и **стандартное отклонение** метрики по фолдам.
> Высокий разброс — признак нестабильности или переобучения.

## Математическая основа

**Линейная регрессия** — модель и функция потерь MSE:

$$
\hat{y} = kx + b, \qquad \mathrm{MSE} = \frac{1}{n}\sum_{i=1}^{n}\left(y_i - \hat{y}_i\right)^2
$$

**MAE:**

$$
\mathrm{MAE} = \frac{1}{n}\sum_{i=1}^{n}\left|\, y_i - \hat{y}_i \,\right|
$$

**Логистическая регрессия** — сигмоида:

$$
\sigma(z) = \frac{1}{1 + e^{-z}}, \qquad z = \mathbf{w}^\top \mathbf{x} + b
$$

**Log loss (бинарная кросс-энтропия):**

$$
\mathcal{L} = -\frac{1}{n}\sum_{i=1}^{n}\left[y_i \log p_i + (1 - y_i)\log(1 - p_i)\right]
$$

**Индекс Джини** (классификация в узле):

$$
G = 1 - \sum_{i=1}^{C} p_i^2
$$

**Энтропия:**

$$
H = -\sum_{i=1}^{C} p_i \log p_i
$$

**Bias–variance decomposition:**

$$
\mathbb{E}\left[(y - \hat{f})^2\right] = \text{Bias}^2 + \text{Variance} + \text{Noise}
$$

**Precision, Recall, F1:**

$$
P = \frac{TP}{TP + FP}, \quad R = \frac{TP}{TP + FN}, \quad F_1 = \frac{2PR}{P + R}
$$

**Accuracy** через матрицу ошибок:

$$
\mathrm{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
$$

**Стандартизация (Z-score):**

$$
z = \frac{x - \mu}{\sigma}
$$

**PCA** — проекция на главные компоненты (собственные векторы ковариационной матрицы),
упорядоченные по убыванию собственных значений (захваченная дисперсия).

## Лучшие практики и подводные камни

- ✅ **Всегда фиксируйте `random_state`** для воспроизводимости.
- ✅ **`stratify=y`** в `train_test_split` для несбалансированных классов.
- ✅ Не оценивайте классификацию только по accuracy — используйте precision/recall/F1/ROC-AUC.
- ✅ Масштабируйте признаки (`StandardScaler`) для линейных моделей, kNN и нейросетей; деревьям это не нужно.
- ✅ Для табличных данных 2025–2026: **LightGBM / CatBoost** часто сильнее Random Forest.
- ✅ При дисбалансе классов: `class_weight="balanced"`, SMOTE или PR-AUC вместо ROC-AUC.
- ✅ Ограничивайте глубину деревьев (`max_depth`, `min_samples_leaf`) — иначе переобучение.
- ✅ В bagging усреднение снижает variance; в boosting контролируйте `learning_rate` и `n_estimators`.
- ⚠️ Номинативные числовые коды (регионы, ZIP) — не числа по смыслу, кодируйте как категории.
- ⚠️ Micro-F1 на несбалансированных данных может скрывать слабый recall редкого класса.
- ⚠️ Test-выборку используйте **один раз** в самом конце; подбор гиперпараметров — на valid / через CV.
- ⚠️ Высокий разброс метрики по фолдам CV — признак нестабильности или переобучения.

## Примеры реальных кейсов

- **Кредитный скоринг:** логистическая регрессия / случайный лес предсказывают
  вероятность дефолта; класс-дисбаланс критичен → упор на recall и ROC-AUC.
- **Прогноз цены авто/недвижимости:** линейная регрессия и градиентный бустинг;
  MAE как понятная бизнесу метрика ошибки в рублях.
- **Отток клиентов (churn):** классификация с `class_weight="balanced"`; feature
  importance подсказывает, какие факторы удерживают клиента.
- **Сегментация клиентов:** K-Means / DBSCAN для маркетинговых кампаний.
- **Поиск мошенничества:** kNN или изоляционный лес по «отдалённым» транзакциям.
- **Табличный бенчмарк:** LightGBM / CatBoost vs логистическая регрессия как baseline.
